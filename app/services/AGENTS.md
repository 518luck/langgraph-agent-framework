# app/services

适用：业务逻辑层，负责把客户端、仓储层和智能体能力真正串起来。

## 必须

- 一个业务流程一个模块；依赖全部从构造注入。
- 持有仓储与客户端，不持有 session。
- 对外方法写成 `async def`。

### 编排

- 顺序固定：查真实信息（DW）→ 组装实体 → 交仓储落库或建索引。
- 配置入口是路径：加载与校验放在本层方法开头。
- 分支按配置的顶层结构走：有哪段做哪段。
- 实体字段来源固定：业务语义来自配置，类型与示例值来自 DW 查询。
- 拆点规则在本层决定（字段/指标的名字、描述、别名各一个点）；仓储只管落库。

### 事务

- 一批业务操作放进同一个 `session.begin()`。
- 跨存储无事务：顺序固定为先落库、再建索引。

### 向量化

- 用注入的 embedding 客户端分批向量化。
- 返回顺序与输入文本顺序必须一致：后面要按同序拼 id 与 payload。

## 禁止

- 写 SQL、构造 ORM 模型：归仓储与 mapper。
- 在方法内 new 客户端或仓储。
- 自己持有 session：事务通过仓储暴露的 session 开。
